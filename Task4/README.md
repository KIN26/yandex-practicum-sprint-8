## Сервис osago-aggregator

### Паттерны

- Retry — для отправки повторных запросов в стаховне компании 
в случае временных сбоев на их стороне
- Timeout — для того чтобы избежать заторов при обращении к 
API страховых компаний
- Circuit Breaker — Если API страховой компании начинает 
отвечать ошибками или таймаутами, Circuit Breaker 
"разрывает цепь" и первое время сразу возвращает ошибку, 
не делая бесполезных вызовов. Это экономит ресурсы и время. 
Периодически он проверяет, восстановился ли сервис
- Transaction Outbox — так как потерять ответ на полученную 
заяку не приемлемо для надежной отправки ответа в core-app следует 
использовать этот 

### Взаимодействие с core-app

Через kafka топик так, его гораздо проще масштабировать, 
в случае падения osago-aggregator заявки не будут теряться 
они сохраняться в кафке для дальнейшей обработки

### Наличие БД
Нужна как минимум для реализации паттерна outbox, как максимум
для репликации заявкок приходящих с core-app

## Сервис Core-app

Для взаимодействия с UI по отправке ответов по заявка следует 
использовать протокол SSE, он достаточно просто в реализации и 
при это даст возможность выводить ответы по заявкам реальном времени
что хорошо улучшит UX.
