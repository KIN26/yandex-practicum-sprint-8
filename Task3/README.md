## Анализ проблем

### Медленная загрузка страниц

**Причины:**

- Монолитная архитектура (`core-app`), которую очень сложно масштабировать под растущей нагрузкой
- Тяжелые синхронные вызовы сервиса `ins-product-aggregator`
- Сервис `ins-product-aggregator` много тяжелых вызовов в сервисы страховых компаний
- База данных в единственном экземпляре

**Риски:**

- Большие сложности при горизонтальном масштабировании создают риск отказа при росте нагрузки
- Рост времени ответа при добавлении новых страховых компаний


### Проблемы с SLA

Один из партнеров нарушает SLA с нагрузкой 250 RPS при разрешенной 20 RPS

**Причины:**

- Отсутствие Rate Limiter
- Прямой доступ к сервисам компании без промежуточного шлюза

**Риски:**

- Один из партнеров влияет на всю систему целом так и на работу других клиентов
- Нет возможности гарантировать SLA
- Финансовые потери

### Медленная реакция на инциденты и проблемы с надежностью

**Причины:**

- Отсутствие мониторинга
- Нет circuit break-ов между сервисами
- БД в одном экземпляре
- Все сервисы находятся в 1 зоне доступности

**Риски:**

- Увеличение времени простоя
- Репутационные потери
- Невозможность быстрого восстановления

### Проблемы данных и согласованности

**Причины:**

- Синхронная репликация данных между сервисами
- Нет механизма retry-ев
- Зависимость от внешних API страховых компаний

**Риски:**

- Увеличение времени ответа `ins-product-aggregator` при добавлении новых страховых компаний
- Сложность поддержания актуальности данных

---

## Решение

1. Перейти на асинхронное взаимодействие между сервисами:
   - core-app -> kafka -> ins-comp-settlement: Данные об оформленных страховках
   - core-app -> kafka -> ins-product-aggregator: Данные об продуктах и тарифа
   - ins-comp-settlement-> kafka -> ins-product-aggregator: Данные об продуктах и тарифа
2. Батчевая выгрузка данных в кафку по продуктам, тарифам и страховкам вместо выгрузки всего и сразу
3. Внедрение Transaction Outbox
    - core-app
    - ins-product-aggregator
4. Внедрение API-Gateway с применением Rate Limiter (per token)
5. Внедрение паттерна Circuit Breaker в сервисах для взаимодействия с системами страховых компаний:
    - ins-product-aggregator
    - ins-comp-settlement
6. Добавления scheduled job для синхронизации данных с страховыми компаниями
7. Внедрение комплексного мониторинга
